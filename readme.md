# Flag 提交脚本

一个面向春秋云境比赛平台接口的 Python 命令行脚本：逐行读取候选 flag，构造请求签名，并按顺序提交到指定题目的接口。脚本支持提交范围控制、请求间隔、限流退避重试和 JSONL 日志记录。

> 仅用于你有权参与和操作的 CTF 比赛或授权测试环境。使用前请确认比赛规则允许自动提交，并遵守平台的请求频率限制。

## 功能

- 从 UTF-8 文本文件读取候选答案，兼容 UTF-8 BOM，自动去除每行首尾空白并忽略空行。
- 为每次请求生成毫秒时间戳、`rs` 和 `Sign` 签名。
- 使用 `curl_cffi` 的 Chrome impersonation 发送 JSON POST 请求。
- 支持从指定候选序号开始，以及限制本次处理的候选数量。
- 默认设置 7 秒请求间隔；响应消息包含“频繁”时，对当前候选进行递增等待后重试。
- 将收到的 HTTP 响应追加记录到 `submit_log.jsonl`。
- 当响应中的 `code` 为整数 `0` 时，按命中处理并立即停止。

## 文件说明

```text
.
├── main.py     # 主脚本
├── readme.md          # 项目说明
├── flag.txt           # 候选答案文件，需自行创建
└── submit_log.jsonl    # 运行后自动创建，追加写入响应记录
```

## 环境与安装

需要 Python 3，以及可访问比赛接口的网络环境。建议使用独立虚拟环境安装依赖。

```bash
python -m venv .venv
```

激活虚拟环境：

```powershell
# Windows PowerShell
.\.venv\Scripts\Activate.ps1
```

```bash
# Linux / macOS / Git Bash
# Git Bash 下使用 source .venv/Scripts/activate
source .venv/bin/activate
```

安装第三方依赖：

```bash
python -m pip install curl_cffi
```

除 `curl_cffi` 外，脚本使用的其他模块均为 Python 标准库。当前项目未锁定依赖版本。

## 使用前配置

### 1. 更新比赛和登录信息

在 `main.py` 的 `build()` 函数中，按你的授权比赛环境修改以下请求体字段：

| 字段 | 含义 | 配置说明 |
| --- | --- | --- |
| `k` | 比赛标识 | 替换为当前比赛请求中的对应值 |
| `question_id` | 题目标识 | 使用接口要求的值；源码注释标注其为 XXTEA 加密后的题目 ID |
| `token` | 登录 Session | 替换为你自己的有效登录凭据 |
| `img_url` | 抓拍相关字段 | 源码使用固定占位值，能否使用取决于当前比赛要求 |

上述字段目前在源码中硬编码，**不能通过命令行或环境变量覆盖**。`answer` 会被候选文件中的内容覆盖；`stamp` 和 `rs` 会在每次请求时重新生成。

如需迁移到其他授权环境，除 `BASE` 外，还应检查 `Host`、`Origin`、`Referer` 等固定请求头，以及签名规则是否匹配。`--endpoint` 仅修改接口路径，不修改这些配置。

> **凭据安全：** 当前源码包含硬编码的登录 token。公开分享或提交到代码仓库前，请移除真实凭据；如果凭据已经泄露，应使其失效或重新登录更新。不要把他人的 token 用作自己的配置。

### 2. 准备候选文件

在脚本同一目录创建 `flag.txt`，每行填写一个完整候选答案，例如：

```text
flag{candidate_001}
flag{candidate_002}
flag{candidate_003}
```

脚本不会自动添加 `flag{}` 包裹，也不会对重复候选去重。空行会被忽略，因此后续参数中的候选序号不一定等于文件的原始行号。

## 快速开始

建议先限制候选数量，确认登录信息、题目标识和接口行为正确：

```bash
python "main.py" --limit 3
```

处理候选文件中的全部答案：

```bash
python "main.py"
```

指定其他候选文件：

```bash
python "main.py" --flags "./candidates.txt"
```

从第 21 个非空候选开始，最多处理 10 个候选：

```bash
python "main.py" --start 21 --limit 10
```

调整接口路径或请求间隔：

```bash
python "main.py" --endpoint /match/red/submit_paper
python "main.py" --delay 10 --rate-wait 7 --rate-retry 5
```

`/match/red/submit_paper` 仅为接口路径示例，是否适用于当前比赛需自行确认。调整间隔时应遵守平台规则，不要通过缩短间隔规避限流。

查看命令行帮助：

```bash
python "main.py" --help
```

## 命令行参数

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--flags` | 字符串 | 脚本所在目录的 `flag.txt` | 候选文件路径；手动传入相对路径时，相对于当前工作目录解析 |
| `--endpoint` | 字符串 | `/match/red/submit` | API 路径，直接拼接到 `BASE` 后面，应以 `/` 开头，不是完整 URL |
| `--limit` | 整数 | `0` | 最多处理的候选数量，`0` 表示全部；不限制重试产生的请求次数 |
| `--start` | 整数 | `1` | 从第几个非空候选开始，序号从 1 起 |
| `--delay` | 浮点数 | `7.0` | 常规请求调度间隔，单位为秒 |
| `--rate-wait` | 浮点数 | `3.0` | 限流后的基础等待时间，第 N 次限流重试前等待 `该值 × N` 秒 |
| `--rate-retry` | 整数 | `5` | 单个候选的额外重试次数上限，网络异常也使用这一计数 |
| `-h` / `--help` | 开关 | — | 显示帮助并退出 |

处理顺序为：读取并清理候选 → 应用 `--start` → 应用 `--limit`。请使用 `--start >= 1`、`--limit >= 0`，并为间隔和重试次数提供非负值；脚本当前没有针对这些取值做额外校验。

## 签名机制

以下描述以当前代码实现为准：

1. `stamp` 为当前 Unix 时间戳，单位为毫秒。
2. `rs` 的生成逻辑为：

   ```text
   rs = MD5(js_num_str(stamp + random.random()) + "icq")
   ```

3. 将请求体中的所有字段转换为 `key=value` 字符串，按字符串排序，用 `&` 连接，并在末尾追加 `&` 和源码中的 `SALT`。
4. 对拼接结果计算 **SHA-1** 十六进制摘要，写入请求头 `Sign`：

   ```text
   Sign = SHA1("&".join(sorted(key=value 字符串列表)) + "&" + SALT)
   ```

参与签名的请求体字段包括 `answer`、`img_url`、`k`、`question_id`、`rs`、`stamp` 和 `token`。`js_str()`、`js_num_str()` 用于模拟签名所需的部分 JavaScript 字符串转换行为，并非完整的 JavaScript 运行时实现。

> 注意：脚本顶部说明把 `SIGN` 写成了 MD5，但 `make_sign()` 的实际实现是 **SHA-1**。本文以实现为准；平台前端或接口更新后，现有签名规则可能不再适用。

## 输出与日志

终端会显示候选数量、当前候选序号、答案、HTTP 状态码及业务响应消息。

每次成功取得并处理响应后，脚本会向**脚本所在目录**的 `submit_log.jsonl` 追加一行 JSON，例如以下示意记录：

```json
{"n": 1, "answer": "flag{candidate_001}", "http": 200, "resp": {"code": 1, "msg": "示例响应消息"}}
```

字段含义：

- `n`：候选在清理后列表中的序号。
- `answer`：本次提交的完整答案。
- `http`：HTTP 状态码。
- `resp`：解析后的响应；无法解析为 JSON 时，记录为包含前 300 个响应文本字符的 `{"_raw": "..."}`。

日志采用追加模式，不会在启动时清空。同一候选的多次响应会分别记录，网络请求抛出的异常只显示在终端，不写入该日志。日志包含完整候选答案及服务端响应，分享前应检查并脱敏。

## 重试与停止规则

- **命中：** 仅当响应对象中的 `code == 0` 时打印命中信息并结束；HTTP 200 本身不代表答案正确。
- **限流：** 当 `msg` 或备用的 `message` 字段中包含“频繁”时，对同一候选执行递增等待并重试。默认基础等待为 3 秒，对应 3、6、9、12、15 秒；超过重试上限后跳过该候选。
- **网络异常：** 请求超时等异常同样消耗当前候选的重试次数，但不会执行上述限流递增等待，仍受常规请求调度控制。单次请求超时配置为 20 秒。
- **其他响应：** 记录结果后继续下一个候选，不会自动判断登录失效、比赛结束等情况并停止。
- **处理结束：** 若全部候选处理完仍未命中，打印结束提示。即使部分候选因异常或限流被跳过，也会进入这一结束分支。

限流冷却结束后会重置下一次请求时间，因此 `--delay` 不应被理解为所有重试场景下都保证的最小请求间隔。

## 常见问题与限制

### 提示找不到 `flag.txt`

默认文件位于脚本目录，且不会自动创建。请创建该文件，或使用 `--flags` 指定已有文件。

### 提示 `No module named 'curl_cffi'`

使用运行脚本的同一个 Python 环境安装依赖：

```bash
python -m pip install curl_cffi
```

### 持续返回“频繁”或登录相关错误

先停止提交，检查比赛规则、平台提示以及 `token`、`k`、`question_id` 是否有效。限流时可按平台要求增加等待时间；不要持续重试无效登录信息。

### 中断后如何继续？

脚本不提供自动断点恢复，也不会从日志推断下一条候选。可检查终端和日志后，通过 `--start` 手动指定继续位置。

### 返回 JSON 后脚本仍然报错

当前响应处理预期服务端返回 JSON 对象。如果接口返回数组、字符串等其他 JSON 类型，后续 `.get()` 调用可能报错。非 JSON 响应会转换为 `_raw` 记录，但不会自动视为命中。

### 其他边界

- 候选文件会一次性全部读入内存，之后才应用范围参数。
- 登录信息、题目参数和部分浏览器请求头固定在源码中，需要手动维护。
- 脚本没有离线演练模式，正常运行会向配置的服务端发送真实请求。
- 当前项目未附带自动化测试或许可证文件；本说明不代表已验证当前线上接口可用，也不授予额外的代码使用许可。
